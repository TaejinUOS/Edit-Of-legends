# EditOfLegends

롤 녹화본의 K/D/A를 로컬에서 읽어 하이라이트 컷을 만들고, Premiere Pro의 새 시퀀스에 배치하는 MVP입니다.

Windows 배포판은 Premiere UXP 패널과 로컬 분석 엔진 설치 프로그램으로 구성됩니다. 로컬 분석·웹 검토 화면은 실제 녹화본으로 테스트합니다. Premiere UXP 어댑터는 구현 및 SDK 모형 테스트를 포함하지만, 실제 타임라인 생성은 별도 호스트 검증이 필요합니다. 이 저장소가 PRD의 정식 출시 조건을 모두 충족한 것은 아닙니다.

## Windows 설치

배포 파일 두 개를 순서대로 설치합니다.

1. `EditOfLegends-Engine-Setup-0.2.2-win-x64.exe`를 실행해 분석 엔진을 설치합니다.
2. `com.taejinuos.editoflegends_premierepro.ccx`를 더블클릭해 Creative Cloud Desktop으로 패널을 설치합니다.
3. Premiere를 다시 시작하고 **Window → UXP Plugins → EditOfLegends**를 엽니다.
4. 최초 엔진 실행 확인 창에서 허용합니다. 선택을 기억하면 이후 패널이 엔진을 자동으로 시작하고 연결합니다.

배포판에는 Node.js, FFmpeg, ffprobe와 OCR 데이터가 포함되므로 사용자가 별도로 설치하거나 `start.ps1`을 실행할 필요가 없습니다. 영상과 분석 데이터는 로컬에서만 처리되며 `%LOCALAPPDATA%\EditOfLegends`에 저장됩니다.

## 빠르게 실행

이 절은 소스에서 개발할 때만 사용합니다. 필요 환경은 Windows 11과 Node.js 22 이상입니다. FFmpeg, ffprobe와 OCR 모델은 npm 패키지에 포함되어 설치 이후 분석할 때 인터넷을 사용하지 않습니다.

```powershell
npm ci
npm start
```

또는 `start.ps1`을 실행합니다. 실행 창에 출력되는 `http://localhost:4317/#...` 주소를 열면 검토 화면이 나타납니다. 터미널을 닫으면 엔진이 종료됩니다. `src-video/` 안의 MP4는 자동으로 선택 목록에 표시되며, 다른 파일은 절대 경로로 불러올 수 있습니다.

개발 실행에서 자동 연결을 사용할 수 없다면 패널의 **기타 설정 → 개발용 연결 파일 선택**에서 `.eol/connection.json`을 선택하세요. 이 파일과 검토 URL의 토큰을 다른 사람에게 공유하지 마세요.

## 사용 순서

1. 녹화본을 불러옵니다. 필요하면 소스 시작/끝 범위를 초 단위로 지정합니다.
2. 실제 게임이 진행되는 시점으로 이동하고 **HUD 영역 설정**을 엽니다.
3. 본인 `K / D / A` 숫자만 포함하도록 영역을 드래그하거나 비율을 입력합니다. **이 프레임 판독**으로 확인합니다.
4. 앞뒤 보존 시간, 동시 판정 시간, 이벤트 유형과 워커 수를 설정한 뒤 분석합니다.
5. 이벤트 목록에서 오탐을 제외하고 시각·유형을 수정하거나 누락 이벤트를 추가합니다. 판독 공백/여러 증가량 후보는 기본적으로 제외되어 있습니다.
6. **생성할 컷** 탭에서 실제 컷의 시작·끝을 수정합니다. 시간 입력은 초이며 출력은 프레임에 맞춰집니다. 다른 컷과 겹치는 수정은 거부됩니다.
7. Premiere 패널에서 완료된 작업을 불러와 **새 시퀀스 생성**을 누릅니다.

이벤트 또는 전역 컷 설정을 바꾸면 이전 수동 컷 경계 조정은 초기화됩니다. 웹 검토 화면의 수정은 로컬에 자동 저장됩니다. Premiere 패널에서 다시 작업을 불러오면 최신 전역 설정까지 반영됩니다.

## Premiere 개발 로드

이 MVP는 서브클립 API를 사용하므로 **Premiere Pro 26.3 이상**을 대상으로 합니다. 개발 PC에서 발견한 버전은 26.5.1입니다. 설치된 버전을 발견한 것과 해당 버전에서 통합 테스트를 통과한 것은 구분합니다.

1. Adobe Creative Cloud에서 **UXP Developer Tool 2.2 이상**을 설치합니다.
2. Premiere의 **Settings → Plugins → Enable developer mode**를 활성화하고 Premiere를 다시 시작합니다.
3. UXP Developer Tool에서 기존 플러그인을 추가하고 `plugin/manifest.json`을 선택합니다.
4. Premiere에 연결된 상태에서 **Load & Watch**를 누릅니다.
5. Premiere의 **Window → UXP Plugins → EditOfLegends** 패널을 엽니다.
6. 로컬 엔진을 실행합니다. 배포용 동반 앱이 없다면 개발용 연결 파일을 선택합니다.

개발 모드와 로드 방식의 근거: [Adobe 공식 플러그인 시작 가이드](https://developer.adobe.com/premiere-pro/uxp/plugins/).

패널에서 **선택 클립 불러오기 → 녹화본 분석 → 검토 → 새 시퀀스 생성**을 진행할 수 있습니다. 웹에서 먼저 분석했다면 동일한 원본을 Premiere 프로젝트에 가져온 후 **작업 새로고침 → 선택 작업 불러오기**를 사용하세요. 확대된 미리보기, HUD 드래그, 시각·유형 수정과 수동 컷 경계 편집은 웹 검토 화면을 사용합니다.

결과는 킬 V1, 어시스트 V2, 데스 V3에 공통 시간축으로 이어집니다. 해당 유형이 없으면 Premiere가 빈 상위 트랙을 만들지 않을 수 있습니다. 오디오는 원본 프로젝트의 채널 매핑을 따라 전달되며, 생성 후 컷 수·출력 위치·길이·오디오 트랙 수를 검사합니다. 기존 시퀀스의 효과, 자막, 주변 오디오는 복제하지 않습니다.

오류·취소 시 새 시퀀스는 `_INCOMPLETE` 이름으로 남으며, 성공 메시지를 표시하지 않습니다. 이미 생성한 EOL 서브클립도 남을 수 있습니다. 기존 시퀀스나 원본 파일을 삭제·수정하지 않습니다.

```powershell
npm run package:plugin
```

이 명령은 `dist/`에 설치 가능한 `.ccx` 패키지를 만듭니다. 전체 Windows 배포본은 다음 명령으로 생성합니다.

```powershell
npm run package:release
```

출력은 UXP `.ccx`와 `EditOfLegends-Engine-Setup-<version>-win-x64.exe`입니다. Windows 설치 프로그램 생성에는 Inno Setup 6이 필요합니다. 공개 배포 전에는 설치 프로그램 코드 서명과 실제 Premiere 호스트 검증을 별도로 완료해야 합니다.

## 지원 범위

| 항목   | MVP                                                                  |
| ------ | -------------------------------------------------------------------- |
| 영상   | MP4 / H.264, 1920×1080 또는 2560×1440, 고정 30/60fps                 |
| 오디오 | 동기화된 AAC 모노/스테레오, 여러 스트림 허용                         |
| 입력   | 한 경기·고정 플레이어 시점, 최대 2시간의 선택 구간                   |
| 분석   | 0.5초 간격, 행/글자별 OCR, 연속 2회 관찰 및 후속 판독으로 변화 확인  |
| 워커   | 자동(최대 4), 1/2/4/8 — 실제 병렬 OCR 워커 수                        |
| 저장   | 성공한 분석 캐시, 작업별 이벤트 수정 및 컷 설정                      |
| 제외   | 리플레이 파일, 관전 전환, VFR, 4K/HEVC, 속도 변경·멀티캠·중첩 시퀀스 |

분석 전 평균 FPS와 실제 패킷 duration을 모두 검사합니다. 이벤트 시각은 **카운터 변화가 샘플에 처음 잡힌 시각**이므로 최대 약 0.5초의 샘플링 오차와 HUD 갱신 지연이 있습니다. 1프레임 단위의 컷 배치는 이벤트 탐지가 1프레임 정확하다는 의미가 아닙니다.

밝기·폰트·HUD 배율과 UI 변경에 따라 OCR 품질이 달라질 수 있습니다. K/D/A가 지속적으로 감소하면 화면 전환 또는 OCR 오류를 표시하고 이후 자동 확정을 중단합니다. 원본 K/D/A가 처음부터 0이 아니면 최초 값을 기준값으로 사용합니다.

## 검증

```powershell
npm test
npm run check
npm run analyze -- "src-video/예시녹화본1.mp4"
# 짧은 구간만 분석
npm run analyze -- "src-video/예시녹화본1.mp4" 630 650
```

- `tests/core.test.js`: 변화 판정, 공백·리셋, 병합·우선순위·필터, 프레임 경계, 수동 컷 수정.
- `tests/server.test.js`: 인증·Origin/Host 제한, 잘못된 입력의 원자성, 수정 저장.
- `tests/premiere.test.js`: SDK 모형을 통한 새 시퀀스 생성 정책, 영상/오디오 배치 및 실패·취소. **실제 Adobe 호스트 테스트를 대체하지 않습니다.**
- `tests/ocr.test.js`: 로컬 예시 파일의 HUD 5개 시점을 읽는 회귀 테스트. 파일이 없으면 건너뜁니다. 녹화본은 저장소에 배포하지 않습니다.
- `tests/integration.test.js`: 실제 미디어의 미리보기·부분 스트리밍·짧은 분석·캐시 재사용·취소를 HTTP API로 검증합니다. 예시 파일이 없으면 건너뜁니다.
- CLI 분석은 `.eol/analysis-report.json`, 성공 캐시와 작업 파일을 생성합니다. CLI 실행 후 웹 엔진을 시작하면 최근 작업에서 불러올 수 있습니다.

실제 측정 결과와 남은 검증 항목은 [검증 기록](docs/VALIDATION.md)을 참고하세요. PRD의 20개 영상 평가, 정밀도/재현율, 5명 사용자 테스트, 설치 패키지 검증은 아직 완료하지 않았습니다.

## 구성

```text
engine/    로컬 HTTP API, FFmpeg 입출력, OCR, 이벤트 판정과 컷 계획
plugin/    Premiere UXP 패널과 직접 시퀀스 생성 어댑터
companion/ Windows 동반 앱 런처와 Inno Setup 설치 정의
scripts/   실행 점검, CLI 분석, UXP 및 Windows 배포 패키징
tests/     핵심 로직·HTTP·호스트 어댑터·실제 HUD 회귀 테스트
.eol/      로컬 작업, 모델 분석 캐시, 연결 토큰 (Git 제외)
src-video/ 사용자 녹화본 (Git 제외)
```

엔진은 Node.js로 구현했습니다. PRD의 Python은 후보 기술이었으며, 현재 환경의 Node.js/FFmpeg와 로컬 WASM OCR을 활용해 별도 Python 설치 의존성을 줄였습니다. 로컬 HTTP는 127.0.0.1에만 바인딩하고 인증 토큰을 요구합니다. 영상·음성·프레임을 외부 서버로 업로드하지 않습니다.

## 문제 해결

분석 캐시는 앱 버전과 독립적인 `engine/core.js`의 `ANALYSIS_REVISION`을 사용합니다. UI·패키징·성능 개선만 있는 앱 업데이트에서는 캐시가 유지되며, OCR·샘플링·이벤트 판정 또는 저장 결과의 호환성이 달라질 때만 이 값을 올립니다. 원본 파일·분석 범위·HUD 영역·샘플 간격 변경은 계속 캐시를 무효화합니다. 앱 버전이 포함된 구형 캐시는 삭제하지 않지만, 새 키와 호환되지 않아 최초 한 번 재분석합니다.

분석 시 FFmpeg 디코딩은 고정 2스레드 대신 CPU 용량에서 OCR 워커와 필터·조정용 여유 2개를 뺀 범위에서 4~8스레드를 비교합니다. 여유가 4개 미만이면 1~3스레드로 낮춥니다. 처음 최대 8초 구간을 OCR과 함께 후보별 정방향·역방향으로 측정하고, 합산 시간이 가장 빠른 설정을 선택합니다(3% 이내이면 적은 스레드 우선). 초기 비교 시간이 추가되며, 선택값과 측정값은 분석 결과의 `decoderThreads`, `threadTrials`에 기록됩니다. 기존 완료 캐시를 불러올 때는 비교하지 않습니다.

동일한 HUD 픽셀과 크기는 분석 세션 내에서 전체 OCR 결과를 재사용합니다. 동시 요청도 공유하며, HUD·글자 캐시는 각각 최대 2,048개로 제한합니다. 이미지가 달라지면 다시 판독하고, 실패한 OCR 요청은 캐시에서 제거합니다.

- **자동 실행 실패:** Windows 동반 앱 설치 여부와 `editoflegends://` 프로토콜 등록을 확인합니다. 개발 환경에서는 `connection.json`을 선택할 수 있습니다.
- **포트 사용 중:** 이미 실행한 EditOfLegends 엔진이 있는지 확인합니다. 여러 엔진을 중복 실행하지 마세요.
- **FFmpeg 없음:** 배포판은 엔진 설치 프로그램을 다시 설치합니다. 개발 환경은 `npm ci`를 다시 실행하거나 `FFMPEG_PATH`, `FFPROBE_PATH`를 지정합니다.
- **판독 불가:** 게임 화면이 보이는 시점에서 세 숫자와 `/`만 들어오도록 HUD 영역을 조절합니다. 로비·로딩 화면에서 0개 판독은 정상입니다.
- **생성 실패:** 오류 메시지와 `_INCOMPLETE` 시퀀스를 확인합니다. 원본 파일의 오프라인 상태, 프레임레이트 및 채널 매핑을 확인한 후 새로 생성합니다.
- **분석 취소/종료:** 진행 중인 분석의 부분 재개는 지원하지 않습니다. 완료된 분석 캐시만 재사용합니다.
